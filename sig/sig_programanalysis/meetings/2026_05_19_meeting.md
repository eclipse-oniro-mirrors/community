**议题3、基于ArkUI的页面设计性能评估与自动化方法研究进展**  
汇报人：吴佳昊  
会议结论：  
1、介绍上次汇报的修改意见：对于主线程上的疑似高耗时操作，增加最后一层过滤，判断其是否真的产生了高耗时影响，而不是盲目误报。例如项目当中非主业务相关的一些路径，虽然在主线程当中进行了计算，但是规模非常小。  
2、介绍 state 模块的实现思路和方法，该模块针对状态机制当中的不必要刷新、深拷贝开销、状态语义混乱等问题。  
3、设计 5 条检测规则：  
   - `SV_WATCH_SELF_TRIGGER`：@Watch 回调直接或间接写回被监听字段，可能形成循环更新链路；  
   - `SV_PROP_HEAVY_COPY`：复杂对象使用 @Prop，且存在明显使用负担，可能引入深拷贝成本；  
   - `SV_STATE_UNUSED_REACTIVE`：@State 声明后没有进入 UI 响应链，本质上更像普通字段或一次性缓存；  
   - `SV_STATE_IMMUTABLE_OVERDECORATED`：@State 确实被 UI 消费，但静态分析未发现后续写入路径，说明响应式声明可能冗余；  
   - `SV_CONSUME_NO_PROVIDER_PATH`：@Consume 在祖先路径上未找到可证实的 @Provide。  
4、主要实现思路：基于 ArkAnalyzer 完成类型推断，之后为每个状态变量构建语义快照，基于 ViewTree 中的自定义组件节点构建祖先关系图，最后进行规则匹配命中。  

**议题4、面向鸿蒙系统的字节码切片与大模型语言理解双驱动的代码分析智能体进展**  
汇报人：李浩远  
会议结论：介绍了 LLMStub 机制与 Want 模型增强的相关内容。LLMStub 机制通过在过程间方法调用边界生成函数摘要（如 JSON 格式的 stub IR），减少复杂函数分析时的分支爆炸问题，简化反向切片流程，提升分析效率与可解释性。同时，优化 Want helper summary，利用 AST 扫描及 LLM 语义摘要恢复 Want 构造字段，增强跨过程 Want 追踪能力。
