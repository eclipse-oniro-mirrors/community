**议题3、面向鸿蒙系统的字节码切片与大模型语言理解双驱动的代码分析智能体进展**  
汇报人：李浩远  
会议结论：  
当前 ArkAnalyzer 已支持 JSON5 解析（如 `build-profile.json5` 等）及工程模块关联，但 `app.json5`/`module.json5` 配置分析未融入主线，导致无法确认 UIAbility 等组件注册状态、`launchType` 及 Want 跳转关系。  
核心问题是切片逻辑仅依赖源码显式调用（如 `onNewWant`），受框架语义约束（如未声明 `launchType` 时无法确认实例复用规则），使得部分生命周期入口（如 `onNewWant`）被保守排除，且 Want 发起的组件跳转仅能定位到 API 调用层。  
解决方案是新增 Harmony 框架旁路层，构建 Registry 解析 `app.json5`/`module.json5`，提取组件名、`launchType` 等关键信息并与源码绑定，通过配置语义约束补充切片判断依据（如 singleton/specified 允许 `onNewWant` 作为有效入口，multiton 默认排除），同时恢复显式 Want 目标关联，将 `startAbility` 调用的目标组件回溯至切片路径。  
技术原理是在原“过程内回溯+过程间扩展”逻辑中，新增 Harmony 框架语义扩展路径，通过 Registry 配置与 Want 目标匹配局部补全隐式分发关系。  
下一步聚焦隐式 Want 解析，包括扩展 Registry 支持 skills、增强 Want 字段恢复能力、增加隐式匹配规则及对复杂动态 Want 降级处理，同步探索与 HomeFlow 结合。
